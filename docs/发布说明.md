# QTCAE Windows 发布说明

## 发布目标

QTCAE 的源代码保存在 Git 仓库中，可运行程序通过 GitHub Releases
发布。不要把 EXE、DLL、PDB、构建目录或大型仿真结果提交到 Git。

普通用户下载 `QTCAE-<版本>-windows-x64.zip`，解压后运行
`QTCAE.Workbench.exe`。开发者通过 Fork、功能分支和 Pull Request
修改源代码。

## 依赖要求

必须使用 Release 版本构建并部署以下运行时依赖：

- Qt 6 Widgets 及 `plugins/platforms/qwindows.dll`；
- OpenCASCADE 运行库、第三方运行库和资源目录；
- VTK Release 运行库；
- Gmsh 运行库；
- Microsoft Visual C++ 2015–2022 Redistributable（x64）。

Debug 版本依赖 Debug CRT，不得作为公开发布包。

Workbench 通过 Gmsh C++ API 直接链接 Gmsh，因此 Gmsh SDK 必须使用
与 QTCAE 相同的 MSVC 工具链和 Release 配置构建。若 Gmsh 二进制使用
MinGW C++ ABI，或链接了 MSVC Debug CRT，不能用于本项目的 Windows
Release 包。打包脚本会扫描所有 EXE/DLL 的直接依赖，并拒绝包含 Debug
CRT 依赖的文件。

## 本地打包

1. 为 `windows-msvc-release` 配置 Qt、OpenCASCADE、VTK 和 Gmsh
   的 Release 安装路径。可以通过脚本参数传入：

   ```powershell
   .\scripts\package-windows.ps1 `
       -Qt6Dir "<Qt>/lib/cmake/Qt6" `
       -OpenCascadeDir "<OCCT>/cmake" `
       -VtkDir "<VTK>/lib/cmake/vtk-9.4" `
       -GmshDir "<Gmsh SDK>"
   ```

   也可以设置 `QTCAE_QT6_DIR`、`QTCAE_OCCT_DIR`、
   `QTCAE_VTK_DIR` 和 `QTCAE_GMSH_DIR` 环境变量。
2. 脚本将执行：

   ```text
   CMake 配置
   → Release 编译
   → CTest
   → CMake Install
   → Qt/OCCT/VTK/Gmsh 运行库部署
   → Debug DLL 检查
   → EXE/DLL Debug CRT 依赖扫描
   → Workbench 冒烟测试
   → ZIP 和 SHA256 生成
   ```

3. 在未安装 Qt、OpenCASCADE、VTK 和 Gmsh 的干净 Windows
   虚拟机或 Windows Sandbox 中验证 ZIP。

## 创建 GitHub Release

确认以下条件后再发布：

- 工作树干净；
- 提交已经合并到 `main`；
- Release 编译和全部测试通过；
- 干净 Windows 环境启动通过；
- 已确定项目许可证；
- 已添加第三方许可证和版权说明；
- 版本标签与 `CMakeLists.txt` 中的项目版本一致。

本地创建并上传 Release：

```powershell
git switch main
git pull --ff-only
git tag -a v0.1.0 -m "QTCAE 0.1.0"
git push origin v0.1.0
.\scripts\publish-release.ps1 -Tag v0.1.0
```

脚本默认发布 `dist` 中与标签版本一致的 ZIP 和 SHA256 文件。
未传入 `-Publish` 时只执行检查并显示将要执行的命令；确认无误后使用：

```powershell
.\scripts\publish-release.ps1 -Tag v0.1.0 -Publish
```

## 许可证注意事项

QTCAE 当前直接链接 Gmsh。公开源代码和发布二进制文件前，必须确认
QTCAE 的整体许可证与 Gmsh、Qt、OpenCASCADE、VTK 及其传递依赖的
再分发条款兼容。未完成许可证确认时，不应创建正式公开 Release。
